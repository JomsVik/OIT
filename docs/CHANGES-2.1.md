# Изменения версии 2.1

* При приёмке и возврате картриджа поля места установки и принтера скрыты. Сервер также не сохраняет эти поля для прихода и возврата.
* Карточку картриджа можно удалить директору или главному администратору при нулевом остатке. Она исчезает из склада; история, штрихкоды и записи движений сохраняются в БД. Ненулевой остаток защищён от случайного удаления. Код удалённой карточки остаётся занят, чтобы не смешивать историю разных моделей.
* Выполнение заявки сохраняет отдельное поле `completion_details`, а исполнителя сервер определяет по сессии. Ни результат, ни исполнитель не отправляются в пользовательские ответы API, включая отслеживание по коду. Запись выполнения не добавляется в комментарии.
* Миграция 005 переносит старый комментарий выполнения в отдельный результат, если он записан тем же исполнителем за последние 10 секунд перед закрытием. Комментарий остаётся в БД с признаком служебной записи и исключается из обсуждения. Более ранние публичные комментарии без таких признаков автоматически не классифицируются: если в них вручную записывали внутренние сведения, их нужно отдельно проверить.
* В инвентаре появились мониторы: модель, производитель, серийный номер, диагональ, разрешение, подключение, ответственный, место и примечание.
* Окна портов и отчётов открываются на весь экран. Даты отображаются как `ДД.ММ.ГГГГ ЧЧ:ММ` в часовом поясе компьютера, даты без времени — как `ДД.ММ.ГГГГ`. В таблицах даты не разбиваются посередине.
* Штрихкоды автоматически преобразуются из русской раскладки в английскую в браузере и на Rust-сервере. Пример: `РЗ85Ф` → `HP85A`. Начальные нули сохраняются.
* Кнопка «Выгрузить БД» доступна только директору. Выгружается согласованная SQLite-копия с данными и учётными записями. Активные сессии и счётчики попыток входа в копию не переносятся. Это полный backup, поэтому храните его с ограниченным доступом.
* Оформление обновлено в духе Cyberpunk 2077: графитовый фон, жёлтые акценты, бирюзовые элементы и угловатые панели. Логотипы и графические материалы игры не используются.

## Где находится Rust

Сервер, авторизация, проверки прав, обработка заявок, складские транзакции и работа с SQLite реализованы на Rust:

* [`src/main.rs`](../src/main.rs) — HTTP-сервер Axum, сессии, права и выгрузка базы.
* [`src/portal.rs`](../src/portal.rs) — заявки, результаты выполнения, инвентарь, задачи, отчёты и сеть.
* [`src/stock.rs`](../src/stock.rs) — картриджи, преобразование раскладки, остатки и журнал.
* [`src/db.rs`](../src/db.rs) — БД и миграции.
* [`Cargo.toml`](../Cargo.toml) — манифест Rust-проекта.

HTML, CSS и JavaScript отвечают за интерфейс браузера. Готовый `oit-portal.exe` — скомпилированная программа на Rust со встроенными файлами интерфейса; Node.js для запуска не нужен. `/api/health` также сообщает используемые Rust / Axum и SQLite.

## Как обновить локальную сборку Windows

1. Создайте резервную копию через `BACKUP-LOCAL.cmd` или кнопку директора «Выгрузить БД».
2. Остановите программу клавишами Ctrl+C в её окне.
3. Скачайте новый [`OIT-Windows-x64.zip`](../releases/OIT-Windows-x64.zip) и распакуйте его в отдельную папку.
4. Замените в своей рабочей папке `oit-portal.exe`, `START-LOCAL.cmd` и `BACKUP-LOCAL.cmd` файлами из нового архива. Сохраните свои `.env`, каталог `data` и копии из `backups`.
5. Запустите `START-LOCAL.cmd`. Новая схема БД применится автоматически. Обновите страницу браузера сочетанием Ctrl+F5.
6. Проверьте приход, выдачу, приватность результата заявки, мониторы и выгрузку БД. Старые отчёты остаются сохранёнными снимками; для новых полей создайте новый отчёт.

Возврат старого исполняемого файла после миграции может требовать соответствующей старой копии базы. Инструкция Word остаётся применима к основному локальному запуску; изменения версии описаны здесь.
